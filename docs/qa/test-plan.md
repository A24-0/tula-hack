# Test Plan: Voice Anonymization Pipeline

**Проект:** tula-hack (voice-redaction)
**Версия:** 1.0
**Дата:** 2026-04-19
**Автор:** QA Engineer

## 1. Введение
Документ описывает стратегию тестирования сервиса анонимизации голоса, состоящего из трёх компонентов: frontend (Vue 3), backend (Go 1.22), ai-service (Python 3.11, Whisper + GigaChat).

## 2. Объект тестирования
- Frontend SPA (`:3000`)
- Backend REST API (`:8080`): `/upload`, `/jobs/{id}`, `/transcript/{id}`, `/audio/{id}/original`, `/audio/{id}/redacted`, `/logs/{id}`
- AI service (`:8000`): `/process`
- Пайплайн end-to-end: загрузка аудио → распознавание → детекция PII → заглушение

## 3. Стратегия тестирования

### 3.1. Виды тестирования

#### По характеру сценариев
- **Позитивное** — TC-001, TC-002, TC-013 (корректный mp3/wav/ogg, ожидаемый результат).
- **Негативное** — TC-003, TC-004, TC-005 (неверный формат, превышение 500 МБ, отсутствие поля `audio`).

#### По критериям запуска программы
- **Статическое** — TC-012 (ревью кода handler.go, ner.py, audio_redact.py, проверка CLAUDE.md, .env.example без запуска).
- **Динамическое** — все остальные кейсы (исполнение через UI/API).

#### По степени автоматизации
- **Ручное** — TC-001…TC-010, TC-013 (через UI и `curl`).
- **Автоматизированное** — TC-006, TC-011 (запуск `go test ./...` в `backend/`).

#### По объектам тестирования
- **Функциональное** — TC-001..TC-007, TC-011, TC-013 (соответствие требованиям пайплайна).
- **Нефункциональное** — TC-008 (нагрузка: 5 параллельных загрузок), TC-009 (безопасность: CORS, MaxBytesReader, отсутствие утечек PII в логах), TC-010 (совместимость: Chrome 120+, Firefox 120+, Edge).

#### По степени знания системы
- **Чёрный ящик** — TC-001..TC-010, TC-013 (работа через публичные API/UI).
- **Белый ящик** — TC-011 (юнит-проверка regex в `ai-service/ner.py`, `go test` в `backend/internal/api`), TC-012 (ревью кода).
- **Серый ящик** — TC-006, TC-007 (интеграция + знание, что job store — in-memory и теряет состояние при рестарте backend).

### 3.2. Необходимость тестирования (цели)

| Цель | Покрывающие кейсы |
|------|-------------------|
| Обнаружить проблемы на ранних этапах | TC-012 (статическое ревью) |
| Гарантировать соответствие требованиям | TC-001, TC-002, TC-013 |
| Обеспечить надёжность и безопасность | TC-007, TC-009 |
| Оценить оптимальную нагрузку и работоспособность | TC-008 |
| Подтвердить удобство использования | TC-010 |
| Оценить влияние на другие компоненты и ПО | TC-006 (backend ↔ ai-service) |

## 4. Объём тестирования
13 тест-кейсов, покрывающих upload-флоу, обработку PII, UI-плеер, интеграцию backend↔ai-service, нагрузку и совместимость браузеров.

## 5. Подходы к тестированию
- Ручные прогоны через UI (`npm run dev`, Chrome DevTools).
- API-проверки через `curl` и `Invoke-WebRequest`.
- Автотесты: `cd backend && go test ./...`.
- Статический анализ: ревью по чек-листу (OWASP top-10 для `/upload`).

## 6. Критерии входа/выхода

### Entry Criteria (раздел 7.1 стандарта)
- ✅ Требования задокументированы в `CLAUDE.md`
- ✅ Тест-план утверждён
- ✅ `docker compose up --build` успешно поднимает все сервисы
- ✅ Smoke (TC-001) пройден

### Exit Criteria (раздел 7.2 стандарта)
- ✅ 100% тест-кейсов выполнены
- ✅ Все Critical и High баги исправлены или приняты как known issues
- ✅ Не более 5 Medium багов
- ✅ Покрытие требований ≥ 95%
- ✅ Итоговый отчёт подписан

## 9. Риски
- GigaChat API недоступен → NER работает только на regex (смягчение: проверить в TC-002).
- Cold start faster-whisper ~90с → увеличить таймаут polling во фронте.
- Job store in-memory → рестарт backend теряет job'ы (TC-007).
