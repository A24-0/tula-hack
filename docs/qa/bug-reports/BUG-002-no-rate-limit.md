# BUG-002: На `/upload` отсутствует rate-limit

**ID:** BUG-002
**Заголовок:** Эндпоинт `/upload` принимает неограниченное число запросов с одного IP — возможен DoS через заполнение диска и очереди

**Приоритет:** Low
**Серьёзность:** Minor
**Компонент:** backend/internal/api
**Окружение:** Windows 11, Docker Desktop 4.x, backend: образ из `docker-compose.yml`

## Описание
В [backend/internal/api/handler.go](../../../backend/internal/api/handler.go) и роутере нет middleware для ограничения частоты запросов. Злоумышленник может за несколько минут забить очередь (buffer=64) и заполнить `UPLOAD_DIR` большими файлами (до 500 МБ каждый), тем самым деградировав сервис.

## Шаги воспроизведения
1. `docker compose up -d`
2. В цикле отправлять: `for i in $(seq 1 100); do curl -F "audio=@samples/ok_ru_30s.mp3" http://localhost:8080/upload & done`
3. Наблюдать рост занятого места в volume `uploads` и длину очереди.

## Ожидаемый результат
При превышении порога (например, 10 запросов/мин с одного IP) — HTTP 429 Too Many Requests.

## Фактический результат
Все 100 запросов приняты с 202; очередь переполняется, дисковое пространство не освобождается (нет чистки orphaned файлов).
