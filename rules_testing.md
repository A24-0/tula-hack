# СТАНДАРТ ТЕСТИРОВАНИЯ ПРОГРАММНОГО ОБЕСПЕЧЕНИЯ

## 1. ОБЩИЕ ПОЛОЖЕНИЯ

### 1.1. Назначение документа
Данный стандарт определяет единые требования и процедуры проведения тестирования программного обеспечения в компании QA Service Lab.

### 1.2. Область применения
Стандарт применяется ко всем проектам, проходящим тестирование в рамках компании.

---

## 2. ВИДЫ ТЕСТИРОВАНИЯ

### 2.1. Обязательные виды тестирования:
- **Функциональное тестирование** (позитивное/негативное)
- **Регрессионное тестирование**
- **Smoke-тестирование** (при каждой сборке)
- **Интеграционное тестирование**

### 2.2. Дополнительные виды (по необходимости):
- Нагрузочное тестирование
- Тестирование безопасности
- UX/UI тестирование
- Кросс-браузерное/кроссплатформенное тестирование

---

## 3. ПРОЦЕСС ТЕСТИРОВАНИЯ

### 3.1. Этапы тестирования:

**Этап 1: Планирование**
- Анализ требований
- Оценка рисков
- Определение объема тестирования
- Составление тест-плана

**Этап 2: Проектирование тестов**
- Создание тест-кейсов
- Подготовка тестовых данных
- Настройка тестового окружения

**Этап 3: Выполнение тестирования**
- Запуск тестов
- Фиксация результатов
- Создание баг-репортов

**Этап 4: Отчетность**
- Анализ результатов
- Подготовка отчетов
- Принятие решения о выпуске

### 4.2. Классификация багов:

**Приоритет (Priority):**
- **Critical** — исправление требуется немедленно (блокирует работу)
- **High** — высокое приоритет (важная функция не работает)
- **Medium** — средний приоритет (есть обходной путь)
- **Low** — низкий приоритет (косметические проблемы)

**Серьезность (Severity):**
- **Blocker** — блокирует тестирование
- **Critical** — критическая ошибка функционала
- **Major** — серьезная ошибка
- **Minor** — незначительная ошибка
- **Trivial** — косметическая проблема

## 5. ЖИЗНЕННЫЙ ЦИКЛ БАГА

```
New → Open → In Progress → Ready for Test → Verified → Closed
           ↓         ↓            ↓
        Rejected  On Hold    Reopened
```

**Статусы:**
- **New** — новый баг
- **Open** — подтвержден, назначен на разработчика
- **In Progress** — в работе
- **Ready for Test** — исправлен, готов к проверке
- **Verified** — проверен, исправление подтверждено
- **Closed** — закрыт
- **Reopened** — reopened (баг воспроизводится)
- **Rejected** — отклонен (не баг/не воспроизводится)
- **On Hold** — отложен

## 7. КРИТЕРИИ

### 7.1. Критерии входа в тестирование (Entry Criteria):
- ✅ Требования задокументированы и утверждены
- ✅ Тест-план утвержден
- ✅ Тестовое окружение готово
- ✅ Сборка передана в тестирование
- ✅ Smoke-тесты пройдены

### 7.2. Критерии выхода из тестирования (Exit Criteria):
- ✅ 100% тест-кейсов выполнены
- ✅ Все Critical и High баги исправлены
- ✅ Не более [X] Medium багов
- ✅ Low баги задокументированы и приняты
- ✅ Достигнуто покрытие требований ≥ [95%]
- ✅ Итоговый отчет подписан

### 7.3. Критерии приемки (Acceptance Criteria):
- ✅ Все обязательные функции работают корректно
- ✅ Нет багов с приоритетом Critical/High
- ✅ Производительность соответствует требованиям
- ✅ Документация актуальна

## 8. МЕТРИКИ ТЕСТИРОВАНИЯ

### 8.1. Основные метрики:

**Test Coverage (Покрытие тестами):**
```
TC = (Выполненные тест-кейсы / Общее количество тест-кейсов) × 100%
```

**Defect Density (Плотность дефектов):**
```
DD = Количество дефектов / Размер кода (KLOC)
```

**Defect Removal Efficiency (Эффективность обнаружения):**
```
DRE = (Дефекты найденные при тестировании / 
       (Дефекты найденные при тестировании + Дефекты найденные после релиза)) × 100%
```

**Test Case Effectiveness (Эффективность тест-кейсов):**
```
TCE = (Тест-кейсы нашедшие дефекты / Общее количество тест-кейсов) × 100%
```

**Pass/Fail Rate:**
```
Pass Rate = (Passed тест-кейсы / Выполненные тест-кейсы) × 100%
Fail Rate = (Failed тест-кейсы / Выполненные тест-кейсы) × 100%
```
